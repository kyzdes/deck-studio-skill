# Deck Studio — HTML-презентация, которую запоминают

Ты собираешь презентацию одним HTML-файлом: сцена 1920×1080, под ней поле из 1800 частиц, которое на каждом слайде складывается в новую фигуру; заголовки проявляются по словам, цифры досчитываются, шаги открываются по клику, у спикера своё окно с таймером и заметками. Файл открывается без интернета и показывается шарингом экрана.

Метод вырос из реальной сборки: 20-минутный доклад перед стратсессией, 20 слайдов, около 30 итераций с автором за день. Автор назвал результат «просто шикарно», и все его правки превращены в правила — они в `references/process.md`.

`<skill>` ниже — базовая папка этого скилла (её путь показан при загрузке).

## Путь за семь шагов

1. **Бриф.** Тема, зал, повод, что зал сделает после, как показывают (обычно шаринг экрана ноутбука) и насколько светлый зал, длительность. Один `AskUserQuestion`, а то, что автор уже сказал, не переспрашивай.
2. **Мудборд.** 6–7 запросов к Mobbin → 20–25 референсов → `moodboard.html` с тремя направлениями и живым движением у каждого → автор выбирает (часто смесь).
3. **Сюжет и тексты.** Если установлен `deck-copy` — загрузи его (носитель «сцена»). `copy.md` по шаблону: бриф, заголовки подряд, слайды. Вычитку отдай агенту `deck-copywriter` в фоне.
4. **Сборка.**
   ```
   python3 <skill>/scripts/new_deck.py ./presentation --title "Название" --minutes 20 --theme dark --accent terracotta
   ```
   В `presentation/src/deck.html` лежит каталог из 20 рабочих макетов: оставь нужные, перепиши тексты, цифры вынеси в `DECK_DATA`. Тема и акцент — атрибуты `<html>` (`data-theme="dark|light"`, `data-accent="terracotta|blue|violet|green|amber|rose|mono"`), цвет бренда — `--accent` в `<style>`. Затем `python3 presentation/src/build.py` → `presentation/index.html`.
5. **Проверка.**
   ```
   python3 <skill>/scripts/check_deck.py ./presentation
   ```
   Тайминг, пустые поля, неизвестные формации, открытые вопросы. Потом скриншоты каждого изменённого слайда и каждого шага, консоль без ошибок (`gotchas.md`).
6. **Итерации.** Автор шлёт скриншот с красной рамкой и фразу. Правь ровно отмеченное, держи `copy.md` в синхроне, пересобирай и снова снимай скриншоты.
7. **Сдача.** Открой `index.html` в браузере автора, напомни клавиши, положи сообщение со ссылками для чата в конец `copy.md` и покажи его текстом.

## Устройство деки

```
presentation/
├── index.html          ← собранный файл: его показывают и пересылают
├── copy.md             ← все тексты и вопросы к автору
└── src/
    ├── deck.html       ← слайды, DECK_CONFIG, DECK_DATA, DECK_SHAPES, тема
    ├── engine.css      ← стили движка (не править — переопределять токенами)
    ├── engine.js       ← частицы, навигация, шаги, окно заметок
    ├── build.py        ← вшивает шрифты, CSS, JS и картинки в index.html
    ├── fonts/fonts.css ← шрифты в base64 (кириллица + латиница)
    └── assets/         ← скриншоты и картинки
```

Слайд — `<section class="slide" data-fx="формация" data-act="раздел" data-time="1:00">` с рубрикой, заголовком `data-a="words"`, телом и `<aside class="notes">`. Подробно — `layouts.md`.

Движок не трогай: всё, что нужно деке, задаётся в `deck.html` — тексты, данные, тема, свои фигуры. Так любую деку можно обновить свежим движком из шаблона.

## Правила, которые нарушают чаще всего

1. **Каждой мысли — своя формация.** Две соседние одинаковые формации дают стоп-кадр: переход частиц и есть главный эффект деки.
2. **У каждого объекта своя фигура.** Три одинаковые сферы над тремя инструментами — заглушка. Нет нужной фигуры — нарисуй её через `DECK_SHAPES` сплошным контуром (`resample`).
3. **Метафору автора воплощай буквально.** Сказал «тут TARDIS» — рамка по клику становится будкой.
4. **Цифр, которых нет, нет.** `null` в `DECK_DATA` → пунктир на слайде и вопрос в `copy.md`. Не выдумывай и не округляй за автора.
5. **Возможности продуктов — только со слов автора.** Красивый придуманный сценарий звучит неверно для тех, кто продуктом пользуется.
6. **Знакомому залу не продают спикера.** Вместо регалий — личная история; призыв — «за этим — ко мне», без плашки с контактами.
7. **Не вешай оговорки, о которых не просили** («по нашей оценке»). Источник — в заметках.
8. **Сцена съедает мелкое.** Текст от 25 px, заголовки от 70 px, никакого неонового свечения за текстом.
9. **Проверяй глазами.** Скриншот после каждой видимой правки; скрытая панель браузера замораживает анимации — делай холостой скриншот перед настоящим.
10. **Внутреннее остаётся у автора.** Скриншоты систем, внутренние ссылки и имена коллег живут в его деке, а не в шаблоне или общих файлах.

## Клавиши (напомни автору при сдаче)

| Клавиша | Действие |
|---|---|
| → ↓ Пробел PageDown Enter | Дальше (сначала шаги внутри слайда) |
| ← ↑ PageUp Backspace | Назад |
| F | Полный экран |
| N | Окно заметок: таймер, заметки, следующий слайд, пустые поля |
| T | Светлая / тёмная тема на лету (до перезагрузки) — если зал оказался светлым |
| A | Следующий акцентный цвет — показать автору варианты |
| H или ? | Справка |
| Цифры + Enter | Перейти к слайду; Home / End — к первому / последнему |

## Чек-лист сдачи

- [ ] `check_deck.py` без проблем: сумма `data-time` равна длительности, пустых полей нет (или автор о них знает)
- [ ] заголовки подряд читаются как рассказ, «не X, а Y» — не больше одного на деку
- [ ] соседние слайды не делят одну формацию, у каждого объекта своя фигура
- [ ] скриншот каждого слайда и шага, консоль без ошибок
- [ ] `index.html` открывается без интернета, окно заметок (N) работает
- [ ] `copy.md` совпадает с декой; в конце — вопросы к автору и сообщение для чата
