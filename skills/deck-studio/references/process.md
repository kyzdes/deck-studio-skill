# Процесс: от «сделай крутую презу» до файла, который открывают на сцене

Разбор реальной сборки (стратсессия, 20 минут, 20 слайдов, около 30 итераций правок за один день). Здесь этапы, контрольные точки и то, что автор поправил: эти правки и есть правила.

## Содержание

1. Бриф — 2. Референсы и мудборд — 3. Сюжет и тексты — 4. Сборка — 5. Проверка — 6. Итерации по скриншотам — 7. Сдача

---

## 1. Бриф (5 минут, до любых картинок)

Спросите одним `AskUserQuestion`, не анкетой в чате:
- **Стиль** — после мудборда (этап 2), не до.
- **О чём и для кого**: тема, зал, повод (стратсессия, курс, питч), что зал должен сделать после.
- **Как показывают**: шаринг экрана ноутбука (самый частый случай) / проектор со сцены / ссылкой. Это решает: 16:9, окно заметок отдельно, без мелкого текста и шумов (видеокодек их мажет).
- **Длительность** → `DECK_CONFIG.minutes`, бюджет на слайд ≈ 1 минута.
- **Свет в зале и цвет бренда** → `--theme` и `--accent` у `new_deck.py` (`themes.md`). Если не знают — тёмная тема, а на месте T переключит её в светлую.

Если автор уже прислал тезисы голосом, не переспрашивайте их: соберите бриф из сказанного и покажите одной таблицей.

Контрольная точка: бриф в трёх строках («кто в зале / что сделают / что унесут») стоит в шапке `copy.md`.

## 2. Референсы и мудборд (15–20 минут)

Подробно — `moodboard.md`. Коротко:
1. 6–7 запросов `search_sections` на Mobbin (герой с частицами, бенто, цифры, редакционная антиква, таймлайн, AI-лонч). Если Mobbin не подключён, ищите по памяти о сайтах-ориентирах (Grok, Squarespace, Clay, Oryzo, Studio Freight, Claude) и скажите автору, что Mobbin недоступен.
2. Скачать 20–25 картинок в отдельную папку, разложить по трём направлениям (A — космос, B — тёплый объект, C — редакция) + блок раскладок для цифр.
3. Собрать `moodboard.html` по шаблону: у каждого направления **живой образец движения** — именно он продаёт стиль, скриншоты его не показывают.
4. Открыть автору и спросить направление; часто выбирают смесь (в нашем случае A + C: тёмный космос и антиква).

## 3. Сюжет и тексты

Подробно — `copy-rules.md`. Порядок:
1. Если установлен плагин **deck-copy** — загрузить его (`deck-copy:deck-copy`), выбрать носитель «сцена» и пресет (для доклада эксперта — «Окопный эксперт»).
2. Написать `copy.md`: бриф, заголовки подряд (titles-test), по каждому слайду рубрика / заголовок / визуал / заметки.
3. Отдать на вычитку агенту **deck-copywriter** в фоне (он пишет `copy-review.md`, сам `copy.md` не трогает), а самим тем временем собирать вёрстку. Принять правки, которые снимают тики («не X, а Y» — один раз на деку), утверждения сверх фактов, канцелярит.
4. Если автор меняет направление разговора («это не пересказ курса, а разогрев перед сессией»), остановите вычитку (`TaskStop`), перепишите сюжет и запустите её заново.

Цифр, которых нет, не выдумывайте: ставьте `null` в `DECK_DATA`, на слайде будет пунктир, в заметках — `[что нужно]`.

## 4. Сборка

```
python3 <skill>/scripts/new_deck.py ./presentation --title "…" --minutes 20 --theme dark --accent terracotta
```
1. В `src/deck.html` лежит каталог из 20 макетов. Оставьте нужные, перепишите тексты, удалите лишнее. Макеты и фигуры — `layouts.md`, `particles.md`.
2. Каждой новой мысли — свой макет и своя формация: соседние слайды с одной формацией не дают перехода частиц.
3. Цифры — в `DECK_DATA`, текст — прямо в разметке, заметки спикера — в `<aside class="notes">`, тайминг — в `data-time` (сумма = длительность).
4. Собственные фигуры (ракета, будка, шестерёнка) — через `window.DECK_SHAPES`, без правки движка.
5. `python3 src/build.py` → `index.html` (шрифты и картинки внутри, без интернета).

## 5. Проверка (после каждой правки, которую видно)

Подробно — `gotchas.md`. Минимум:
- `python3 <skill>/scripts/check_deck.py ./presentation` — тайминг, пустые поля, неизвестные формации, открытые вопросы.
- Скриншоты в браузере каждого изменённого слайда (и шагов по клику) + консоль без ошибок.
- Встроенный браузер не читает `~/Desktop` → собранный файл копировать в scratchpad и раздавать оттуда; временную запись в `.claude/launch.json` убрать после проверки.

## 6. Итерации по скриншотам

Автор присылает скриншот с красной рамкой и одну фразу, часто голосом. Как работать:
- Править **ровно отмеченное** в том же ходе, остальное не трогать.
- Диктовку читать по смыслу: «SEO» = CPO, «пока вспять» = «пока вы спите», «10 лет» в контексте последних месяцев — скорее «10 месяцев». Своё прочтение назовите одной строкой в ответе.
- Правки приходят посреди работы — подхватывать их сразу, не откладывая.
- После каждой правки: `copy.md` в синхроне, нумерация слайдов, сумма `data-time` = цель.
- Если автор скидывает материалы (скриншот метрик, отзывы, скрин инструмента, ссылки), сразу превращайте их в слайд и говорите, что сознательно не вынесли и почему (например, три разных NPS рядом путают зал).

## 7. Сдача

- Открыть `index.html` в браузере, который автор указал в своих инструкциях (например, `open -a "Comet" <файл>`), иначе — в браузере по умолчанию.
- Напомнить клавиши: F — полный экран, N — окно заметок с таймером, стрелки и кликер, шаги по клику на слайдах …
- Если в деке есть инструменты или ссылки, в конце `copy.md` положить готовое сообщение в чат и показать его текстом в ответе.
- Обновить память проекта: что решено, что ждёт автора.

## Что автор правил — и почему это правила

| Правка | Правило |
|---|---|
| «Не продавай меня как CPO — все меня знают» | Регалии знакомому залу не нужны: вместо фактов-плашек — личная история (как пришёл к теме) |
| «Забудьте про работу» → «без ИИ стратегию не написать» → «не исполнить» | Глагол в крючке решает смысл; предлагайте вариант и меняйте сразу |
| «Пока вы спите» — убери, скажи, что это комбайн в облаке | Возможности инструмента — только со слов автора; придуманный сценарий легко звучит неверно |
| «По нашей оценке» — убери | Не вешать на слайд оговорки, о которых не просили; источник — в заметках |
| «Контакт смотрится странно; просто „за этим — ко мне“» | Зал знает спикера: плашка без имени и контакта |
| «Три одинаковые сферы — сделай разные» | У каждого объекта своя фигура; одинаковые фигуры читаются как заглушка |
| «Шестерёнка кринжовая» | Иконки из частиц — сплошным контуром с равномерными точками (`resample`), без «скобок» |
| «Выведи ссылки крупно, кину в чат» | Слайд «Где взять» после инструментов + текст для чата |
| «Покажи скриншот инструмента отдельно» | Живой скриншот в рамке окна сильнее описания |
| «Тут TARDIS вместо облака» | Метафору автора воплощать буквально: рамка → будка, которая внутри больше |
